# 데스크톱 퍼블리싱

기준: `설계안.md`, `API명세서.md`, `design/QR_생성_전체_화면시안_수정본.svg`. 확인일: 2026-10-10.

화면·문구·입력 오류·모달 및 예시 화면 전환을 구현했다. 실제 비로그인 QR 생성·다운로드는 동작한다. 계정 화면의 예시 전환은 실제 OAuth·DB·서버 API 구현 완료를 의미하지 않는다.

## 화면 확인

루트에서 `npm run dev` 또는 `npm run build` 후 `npm run preview`를 실행한다.

- `/`: 실제 비로그인 앱. 다섯 유형 입력, 오류, 생성, PNG/SVG 다운로드, 로그인 안내와 비로그인 진입.
- `/publishing.html`: 예시 화면 모음. 상단 `확인할 화면`에서 15개 상태를 선택한다. 모달이 열려 있으면 먼저 취소·닫기 또는 Escape로 닫는다. 요청 중에는 창을 닫거나 중복 실행할 수 없다.
- `/publishing.html?screen=list`: 내 QR 목록부터 시작. 예시 생성 화면에서 저장한 항목도 현재 탭에서만 유지한다.

미리보기에는 `예시 데이터 · 실제 로그인·계정 저장은 연결 전입니다.`를 표시한다. 브라우저 저장소와 계정 API를 사용하지 않는다. 실패 예시는 첫 저장·다운로드·삭제 실행 시 실패하며 이후 재시도로 복구한다. `unavailable`은 목록 새로고침만 제공한다.

## SVG 화면 대응

| 로컬 SVG 화면 | 구현 및 확인 방법 |
| --- | --- |
| URL/Wi-Fi/연락처/텍스트/이메일 정상·오류 10개 | `/`에서 유형 탭을 전환하고 정상·잘못된 값을 입력 |
| Wi-Fi 비밀번호 보기 1개 | 비밀번호 옆 보기·가리기, 공개 네트워크 전환 및 유형 전환 시 가림 복원 |
| 용량 초과·생성 실패 2개 | 긴 텍스트 입력; 생성 실패는 브라우저 검사의 생성기 오류 주입으로 확인 |
| 로그인 정상·실패 2개 | `screen=login`, `login-error`; 비로그인으로 사용하기 제공 |
| QR 저장 창·실패 2개 | `screen=save`, `save-error`; 빈 이름 오류, 요청 중 잠금, 재시도 |
| 내 QR 목록·빈 목록 2개 | `screen=list`, `empty`; 유형 필터, 안전한 요약, 새 QR 만들기 |
| 저장 QR 다운로드·실패 2개 | `screen=download`, `download-error`; 단일 다운로드 버튼에서 PNG/SVG 선택 |
| QR 삭제 확인 1개 | `screen=delete`; 취소 또는 QR 삭제 확인 |
| 비로그인 다운로드·실패 2개 | `/`에서 QR 다운로드; 파일 준비 실패 주입 검사 |

총 24개 SVG 화면에 대응한다. 로그인 완료는 별도 성공 페이지 없이 인증된 헤더와 생성·내 QR 화면으로 전환한다. 예시 모음에는 삭제 실패, 저장·다운로드 인증 만료, 접근 불가, 목록 로딩·조회 실패 상태도 있다.

이후 사용자가 GitHub 가입·로그인 통합 흐름의 시안을 먼저 요청하여 로컬 SVG에 인증 진행·팝업 차단·원래 화면 복귀 3개를 추가했다. 수정본은 27개 화면이며 추가 3개 상태와 자동 가입 안내 문구는 **아직 웹앱 미반영**이다. 해당 시안은 `design/QR_GitHub_가입로그인_와이어프레임.svg`에서도 확인한다. 웹앱은 계속 기존 24개 시안을 기준으로 동작하며 실제 인증 서버는 연결 전이다.

CSS Modules와 CSS 변수로 색상·간격·글꼴을 공유한다. Noto Sans KR이 없으면 시스템 한글 글꼴을 사용하므로 글자 폭은 환경에 따라 다를 수 있다. 이번 완료 범위는 데스크톱이다.

## 서버 연결 지점

| 컴포넌트 | 연결할 동작 |
| --- | --- |
| `Header`, `LoginPage`, `App` | 로그인 정보·로그아웃·GitHub 로그인 시작과 콜백, 원래 탭의 입력 복귀 |
| `SaveDialog` | 이름·유형·페이로드·요청 키 전달; 성공 후 목록 전환 |
| `MyQrPage` | 안전한 목록 메타데이터·총 수·유형 필터·다음 페이지·미리보기 URL, 로딩·오류·새로고침 |
| `DownloadDialog` | 저장 QR ID와 선택 형식으로 파일 준비, 인증 만료와 접근 불가 처리 |
| `DeleteDialog` | 서버 삭제 성공 후 항목 제거, 실패 시 항목 유지 |

콜백을 통해 연결하도록 분리했고 `publishing/fixtures.ts`의 예시 페이로드는 실제 앱 진입점에서 사용하지 않는다. 내 QR의 URL 요약은 호스트만 표시한다. 저장 실패·재로그인 후 재시도는 같은 요청 키를 유지하고, 이름·유형·페이로드가 바뀌면 새 키를 만든다. 다운로드 재로그인에서는 선택한 형식을 유지한다.

실제 구현은 API 명세 P01 인증 → P02 암호화 저장·목록·삭제 → P03 저장 페이로드 파일 재생성 순서로 진행한다. 세션·CSRF·PKCE, 소유권 검사, 암호화 저장, 실제 로그인·타인 접근 차단·저장·재다운로드·삭제 검증은 서버 단계에 남아 있다.

## 검사

`npm test`, `npm run typecheck`, `npm run build`, `npm run test:browser`를 실행한다. 브라우저 검사는 실제 다운로드 파일을 sharp와 jsQR로 읽어 원래 페이로드와 비교한다. 예시 화면 전환 검사와 실제 계정 API 검증을 구분한다. 최종 실행 결과는 `구현현황.md`에 기록한다.
