# 범용 QR 생성 웹페이지 설계

작성일: 2026-10-09

수정일: 2026-10-10 (비로그인 직접 다운로드 및 계정 보관 흐름 분리)

## 목표

사용자가 URL, Wi-Fi, 연락처, 일반 텍스트, 이메일 중 하나를 선택해 고정형 QR 코드를 미리본다. QR 내용이 바뀌면 새 코드를 생성한다. 로그인 없이 입력·미리보기·PNG/SVG 다운로드를 이용할 수 있다. GitHub 계정으로 로그인하면 QR을 계정에 보관하고 `내 QR`에서 다시 다운로드하거나 삭제할 수 있다.

사용자가 말한 비로그인 QR의 ‘일회용’은 계정에 보관하지 않는다는 의미로 확정했다. 다운로드한 파일은 여러 번 스캔할 수 있고 새로고침 후에도 사용할 수 있다. 한 번 스캔하면 만료시키는 기능은 이번 범위에 포함하지 않는다.

## 범위

- 입력 유형: URL, Wi-Fi, 연락처, 일반 텍스트, 이메일
- QR 출력: 검정 코드와 흰 배경, 필수 흰 여백 포함
- 파일 다운로드: PNG와 SVG
- 비로그인 직접 다운로드, 계정 보관 없이 현재 탭에서 생성
- 데스크톱 화면과 키보드 조작 지원. 모바일 시안은 이번 작업에서 제외
- GitHub 계정 로그인, 내 QR 저장·목록·재다운로드·삭제
- 이번 버전에서 제외: QR 중앙 아이콘·로고, QR 색상 변경, 동적 QR, 전화·SMS 전용 입력, 대량 생성

## 화면과 사용 흐름

데스크톱에서는 왼쪽에 유형 선택과 입력 폼, 오른쪽에 QR 미리보기와 실행 버튼을 둔다. 비로그인일 때는 기본 버튼 `QR 다운로드`와 보조 버튼 `로그인하고 저장`을 제공한다. 로그인 상태에서는 `QR 저장하기`를 제공한다. 상단에는 페이지 제목과 로그인·내 QR 진입점을 놓는다. 선택된 유형은 분명하게 강조한다.

로그인 안내 화면에서 `GitHub로 계속하기` 아래에 `비로그인으로 사용하기` 버튼을 둔다. 이를 누르면 로그인 없이 생성 화면으로 이동하고 기존 입력을 유지한다. 로그인 실패 화면에도 같은 버튼을 제공한다. 생성 화면에 직접 들어온 비로그인 사용자도 별도 로그인 화면을 거치지 않고 사용할 수 있다. 비로그인 상태에서 `내 QR`에 진입하면 로그인 안내 화면을 표시한다.

1. 사용자가 다섯 유형 중 하나를 선택한다.
2. 해당 유형에 필요한 항목만 입력한다.
3. 유효한 입력이면 QR 미리보기가 즉시 갱신된다.
4. 비로그인은 `QR 다운로드`를 누르고 PNG 또는 SVG를 선택해 현재 QR을 바로 받는다. 로그인이나 계정 저장을 요구하지 않는다.
5. 계정에 보관하려면 `로그인하고 저장`을 누른다. 별도 인증 창에서 GitHub 로그인을 마친 뒤 원래 입력을 유지하고 저장 창을 연다. 이미 로그인했다면 `QR 저장하기`를 누른다. QR 이름과 보관 정보를 확인하고 저장을 완료한다.
6. `내 QR`에서 저장된 항목의 `다운로드`를 누르고 PNG 또는 SVG를 선택한다.
7. 필요 없는 보관 항목은 `QR 삭제`를 누르고 확인 창을 거쳐 삭제한다.

유형을 바꿔도 각 유형의 입력값은 현재 탭이 열려 있는 동안 메모리에 유지한다. GitHub 인증은 별도 창에서 진행해 원래 탭의 미저장 입력을 유지한다. 새로고침하거나 탭을 닫으면 저장하지 않은 값은 사라진다. 다운로드한 파일에는 영향을 주지 않는다. 입력이 유효하지 않거나 QR 생성이 실패하면 이전 QR을 결과로 보여주지 않고, 수정할 항목과 이유를 폼 가까이에 표시하며 다운로드·저장 동작을 비활성화한다.

화면은 흰색 바탕, 짙은 본문 글자, 선택된 유형과 주요 버튼에만 절제된 파란색 강조를 사용한다. 입력 영역과 결과 영역을 분리해 현재 입력과 내려받을 QR을 한눈에 연결할 수 있게 한다. QR 이미지 자체의 색상은 화면 테마와 관계없이 검정·흰색을 유지한다.

## 유형별 입력과 QR 내용

| 유형 | 입력 항목 | QR에 담을 내용과 확인 규칙 |
| --- | --- | --- |
| URL | 웹 주소 필수 | `http://` 또는 `https://`로 시작하는 유효한 주소를 그대로 담는다. 프로토콜이 없거나 다른 프로토콜이면 수정 안내를 표시한다. 메뉴, 행사, 설문, 상품, 결제 페이지도 URL 유형으로 처리한다. |
| Wi-Fi | 네트워크 이름 필수, 보안 방식 선택, 비밀번호 사용 네트워크라면 비밀번호 필수 | `WIFI:T:WPA;S:<SSID>;P:<비밀번호>;;` 또는 공개 네트워크의 `WIFI:T:nopass;S:<SSID>;;`를 생성한다. 기업용 인증과 WEP는 제외한다. SSID와 비밀번호의 특수문자는 아래 규칙으로 이스케이프한다. |
| 연락처 | 성·이름을 별도 입력하며 둘 중 하나 이상 필수, 전화번호·이메일·회사·웹사이트 선택 | 입력 내용을 `FN`과 `N`이 포함된 vCard 3.0 문자열로 만든다. 아래의 이름 구성·이스케이프 규칙을 따른다. |
| 일반 텍스트 | 내용 필수 | 입력한 UTF-8 텍스트를 담는다. 앞뒤 공백만 있는 값은 허용하지 않는다. |
| 이메일 | 받는 주소 필수, 제목·본문 선택 | `mailto:` URI를 생성하며 제목과 본문은 URL 인코딩한다. 스캔은 메일 작성 화면을 여는 동작이며 메일을 자동 발송하지 않는다. |

Wi-Fi 보안 방식은 사용자가 이해하기 쉬운 `비밀번호 사용`과 `공개 네트워크`로 표시하고, QR에는 각각 `WPA`와 `nopass`를 넣는다. 공개 네트워크를 선택하면 비밀번호 입력은 숨기고 QR의 `P` 항목도 생략한다. 다시 비밀번호 사용을 선택하면 이전에 입력한 비밀번호를 복원한다. 비밀번호는 기본적으로 가리고, 키보드로 조작할 수 있는 보기·가리기 버튼을 제공한다. 폼에는 QR을 받은 사람이 네트워크 이름과 비밀번호를 알아낼 수 있다는 안내를 표시한다.

SSID와 비밀번호는 앞뒤 공백을 자동으로 지우거나 내용을 바꾸지 않는다. 빈 문자열만 필수값 오류로 처리하므로 공백으로 시작하거나 끝나는 실제 네트워크 정보도 그대로 담긴다. QR 문자열을 만들 때 두 값에 포함된 `\`, `;`, `,`, `"`, `:` 앞에는 `\`를 붙인다. 사용자 입력 자체에는 역슬래시를 추가하지 않는다. 값이 짝수 길이의 ASCII 16진수 문자로만 이루어졌다면 스캐너가 16진수 바이트로 오인하지 않도록 이스케이프한 값의 바깥을 큰따옴표로 감싼다. 단, 비밀번호가 64자리 16진수 암호키라면 감싸지 않는다. 줄바꿈과 제어 문자는 연결 호환성이 낮으므로 해당 필드에서 오류로 알린다. 특수문자가 있어도 사용자가 직접 이스케이프 문자를 입력할 필요는 없다. [ZXing의 Wi-Fi QR 형식](https://github.com/zxing/zxing/wiki/Barcode-Contents)을 기준으로 한다.

연락처의 성과 이름은 별도 칸에 입력한다. 둘 다 비어 있을 때만 이름 오류를 표시한다. 앞뒤 공백은 제거하고, 비어 있는 쪽은 빈 구성 요소로 둔다. `N:<성>;<이름>;;;`을 만들고, 표시 이름인 `FN`은 입력된 성과 이름을 이 순서로 한 칸 띄어 이어 붙인다. 예를 들어 `성=김`, `이름=민지`이면 `N:김;민지;;;`과 `FN:김 민지`가 된다. vCard에는 `BEGIN:VCARD`, `VERSION:3.0`, `N`, `FN`, 선택 항목, `END:VCARD`를 넣고 줄 구분에는 CRLF를 사용한다. 텍스트 값의 역슬래시, 세미콜론, 쉼표, 줄바꿈을 vCard 규칙에 따라 이스케이프하고, 긴 줄은 규격에 맞게 접는다. 웹사이트 항목은 유효한 `http://` 또는 `https://` 주소로 확인한다. [vCard 3.0 규격](https://www.rfc-editor.org/info/rfc2426/)을 따른다.

긴 내용이 QR 라이브러리의 용량을 넘으면 내용을 줄이라는 오류를 표시한다. 그 밖의 생성 실패는 현재 입력을 유지하고 다시 생성을 시도할 수 있게 한다. 정확한 문구와 동작은 아래 `시안 보완 확정 UI`를 따른다.

이메일 QR은 한 개의 일반 이메일 주소를 대상으로 한다. 본문 줄바꿈은 [RFC 6068 §5](https://www.rfc-editor.org/rfc/rfc6068#section-5)에 따라 CRLF로 맞춘 뒤 `%0D%0A`로 인코딩한다. 제목에는 줄바꿈·제어 문자를 허용하지 않는다. 주소의 로컬 부분은 비어 있거나 점으로 시작·끝나거나 연속된 점을 포함할 수 없다. 초기 입력기는 ASCII 로컬 부분과 DNS 도메인(국제화 도메인은 punycode 표기)을 지원하며, 인용된 로컬 부분·도메인 리터럴·여러 받는 주소·국제화 로컬 부분은 지원하지 않는다. 연락처의 선택 이메일도 같은 주소 검증을 사용한다.

## QR 출력과 다운로드

QR은 검정색 코드와 흰색 배경으로 만들고, 모든 방향에 최소 4모듈의 흰 여백을 포함한다. 중앙 아이콘이나 로고를 겹치지 않는다. [DENSO WAVE의 여백 지침](https://www.qrcode.com/en/howto/code.html)을 따른다.

PNG는 정사각형 1024×1024픽셀로 내보내고, SVG는 크기를 바꿀 수 있는 벡터로 내보낸다. 두 파일 모두 대상 QR과 같은 내용 및 여백을 가진다. 파일명은 `qr-url.png`, `qr-wifi.svg`처럼 유형을 포함한다.

비로그인은 생성 화면의 `QR 다운로드`에서 파일 형식을 선택한다. 선택 창을 열 때의 유효한 현재 입력과 QR 결과를 대상으로 브라우저에서 파일을 준비한다. 인증 API·저장 API를 호출하거나 계정에 항목을 추가하지 않는다. 안내는 `계정에 보관하지 않아요. QR은 여러 번 스캔할 수 있어요.`이며, 창을 닫으면 입력 화면으로 돌아간다. 형식을 선택하면 다운로드를 시작하고 처리 중 중복 실행을 막는다.

로그인 사용자는 `내 QR`의 다운로드 버튼에서 파일 형식을 선택한다. 다운로드 직전에 사용자 소유의 저장된 페이로드로 QR을 다시 생성한다. 저장된 내용과 미저장 현재 입력을 혼용하지 않는다.

## 내부 구성과 데이터 흐름

- **유형별 폼**: 입력과 필드 오류를 관리한다.
- **페이로드 변환기**: 유형별 값을 URL, Wi-Fi 문자열, vCard, 원문 텍스트, `mailto:` URI로 변환한다. 화면과 QR 라이브러리의 세부 구현에서 독립된 함수로 둔다.
- **QR 생성기**: 유효한 페이로드를 QR 행렬과 SVG로 생성한다.
- **내보내기**: 같은 SVG를 PNG로 래스터화하거나 SVG 파일로 내려받는다.

로그인하지 않은 사용자의 QR 입력·미리보기·다운로드 파일 준비는 브라우저에서 처리한다. 입력과 페이로드를 서버, localStorage, sessionStorage, IndexedDB에 보관하지 않는다. 현재 탭 메모리에서만 유지하며 다운로드 시에도 자동 저장하지 않는다. 이후 로그인해도 명시적으로 계정 저장을 완료한 항목만 `내 QR`에 나타난다.

로그인한 사용자가 `QR 저장하기`를 누르면 계정에 연결된 저장소에 유형, 제목, 생성에 필요한 QR 페이로드, 생성일을 보관한다. 저장된 페이로드로 PNG·SVG를 다시 생성한다. Wi-Fi 비밀번호와 연락처 정보는 다운로드에 필요한 페이로드에 포함될 수 있으므로 저장 전에 이 사실을 알리고, 계정 간 접근을 분리하며 저장 데이터는 암호화한다. 목록에는 Wi-Fi 비밀번호와 연락처 세부 내용을 표시하지 않는다. `QR 삭제` 확인 후 항목을 목록과 저장소에서 제거한다. 고정형 QR이므로 다운로드 후 QR에 담긴 내용은 변경할 수 없다. 계정에서 삭제해도 이미 다운로드한 파일 자체를 만료시키거나 회수하지 않는다.

## GitHub 로그인 및 내 QR

GitHub 계정 인증에는 GitHub의 OAuth 웹 흐름을 사용한다. 클라이언트 비밀값과 사용자 세션은 서버에서 관리하고, 인증 요청에는 상태 검증과 PKCE를 적용한다. QR 저장을 위해 GitHub 저장소 접근 권한은 요청하지 않는다. 계정 식별과 애플리케이션의 QR 데이터 저장을 분리한다. 로그인 실패·취소 시 현재 입력을 유지하고 다시 시도할 수 있게 한다. 로그인 후 `내 QR` 목록에는 유형, 사용자가 정한 제목, 민감하지 않은 요약, 생성일, 단일 `다운로드` 버튼, `QR 삭제` 버튼을 제공한다. 다운로드를 누르면 파일 형식 선택 창을 열고, QR 삭제는 확인 창을 거쳐 실행한다. 항목이 없는 경우 빈 화면과 새 QR 만들기 동작을 보여준다.

2026-10-10 사용자 확인: 내 QR의 URL 요약은 API 명세대로 호스트(`example.com`)만 표시한다. 경로·쿼리·fragment는 목록 문구에서 제외하며 QR에 담기는 원래 주소는 유지한다. 로컬 SVG의 목록 요약 네 곳도 같은 기준으로 맞췄다.

화면 시안의 QR 무늬는 예시이며 실제 스캔용 코드는 아니다.

## 오류와 접근성

필수값 누락, 잘못된 URL·이메일, QR 용량 초과, 생성·저장·다운로드 실패를 각각 이해하기 쉬운 한국어 문장으로 알린다. 오류는 관련 입력 옆에 표시하고 해당 입력과 프로그램 방식으로 연결한다. 탭, 폼, 저장·다운로드·QR 삭제 버튼은 키보드로 사용할 수 있고 선택 상태와 비활성화 상태가 화면과 보조 기술에 전달되어야 한다. QR 미리보기에는 선택 유형과 QR의 목적을 설명하는 대체 텍스트를 제공한다.

## 시안 보완 확정 UI

2026-10-10 사용자가 원본 시안에 없는 다음 항목의 결정을 위임했다. 아래 내용은 `design/QR_생성_전체_화면시안_수정본.svg`와 데스크톱 화면 컴포넌트에 반영했다. 계정 관련 동작은 퍼블리싱 예시로 확인하며 실제 서버 연결과 검증은 남아 있다. 시안 수정은 항상 로컬 SVG로 전달하고 사용자가 Figma에 붙여넣는다.

### 와이파이 비밀번호 보기·가리기

- 비밀번호 입력칸 오른쪽에 `보기` 텍스트 버튼을 둔다. 누르면 비밀번호가 보이고 버튼 문구가 `가리기`로 바뀐다. 다시 누르면 가린다. 눈 모양 아이콘만으로 의미를 전달하지 않는다.
- 기본 상태는 가림이다. 공개 네트워크로 바꾸거나 다른 QR 유형으로 이동하면 보기 상태를 해제한다. 비밀번호 사용으로 돌아올 때 기존 입력값은 복원하되 가린 상태로 표시한다.
- 공개 네트워크에서는 비밀번호 필드와 버튼을 함께 숨기고 페이로드에 비밀번호를 넣지 않는다.
- 버튼은 키보드의 Tab으로 접근하고 Enter/Space로 조작한다. 접근성 이름은 각각 `비밀번호 보기`와 `비밀번호 가리기`이며, 눌림 상태를 전달한다. 토글 후 포커스를 유지하고 입력값이나 QR 내용을 바꾸지 않는다.
- 입력 아래 안내는 `QR을 받은 사람은 네트워크 이름과 비밀번호를 확인할 수 있어요.`로 확정한다.

### 오류 위치·문구·복구 동작

오류는 사용자가 작업 중인 화면 또는 창 안에 표시한다. 기존 시안의 붉은 오류 문구와 옅은 붉은 배경을 사용하며, 색상과 함께 문구로도 실패를 알린다. 새로운 전체 페이지로 이동시키지 않는다.

| 상태 | 표시 위치와 정확한 문구 | 동작 |
| --- | --- | --- |
| QR 용량 초과 | 해당 입력 폼 하단과 미리보기 오류 영역: `내용이 너무 길어요. 내용을 줄여 다시 시도해 주세요.` | 이전 QR을 숨기고 다운로드·저장을 비활성화한다. 입력값은 유지한다. 내용을 수정하면 자동으로 다시 생성하며, 성공 시 오류를 지운다. 같은 내용을 반복 생성하는 재시도 버튼은 제공하지 않는다. |
| QR 생성 실패 | 미리보기 오류 영역: `QR을 만들지 못했어요. 내용을 확인하고 다시 시도해 주세요.` | 이전 QR을 숨기고 다운로드·저장을 비활성화한다. 입력을 유지하며 `다시 생성` 버튼으로 현재 입력을 재시도한다. 입력을 수정해도 자동으로 다시 생성한다. |
| QR 저장 실패 | 저장 창의 제출 버튼 위 안내 상자: `QR을 저장하지 못했어요. 잠시 후 다시 시도해 주세요.` | 창과 QR 이름·입력을 유지한다. 제출 버튼 문구는 `다시 저장`으로 바꾼다. 성공이 확인되기 전에는 창을 닫거나 내 QR에 새 항목을 추가하지 않는다. 서버 결과가 불명확한 경우 같은 저장 요청의 결과를 확인하거나 같은 요청 식별자로 재시도하여 중복 저장을 방지한다. |
| QR 다운로드 실패 | 다운로드 형식 선택 창 하단 안내 상자: `파일을 준비하지 못했어요. 잠시 후 다시 시도해 주세요.` | 창과 선택한 형식을 유지한다. `다시 다운로드` 버튼은 선택한 형식으로 재시도하며, PNG·SVG 선택도 계속 가능하다. 비로그인은 현재 입력·QR 결과를 유지하고 인증을 요구하지 않는다. 계정 다운로드는 저장된 QR을 삭제하거나 목록에서 숨기지 않는다. |

용량 초과와 생성 실패의 미리보기 제목은 기존 오류 시안의 `QR을 만들 수 없어요`를 유지한다. 필수값·URL·이메일 등 입력 검증 오류의 기존 유형별 문구는 그대로 사용한다.

저장·다운로드 요청 중에는 실행 버튼을 비활성화하고 `저장 중…` 또는 `파일 준비 중…`을 표시해 중복 실행을 막는다. 실패 후에는 재시도 동작을 다시 활성화한다. 계정 저장·내 QR 다운로드에서의 인증 만료는 일반 재시도를 반복하지 않고 `GitHub 로그인 후 다시 시도해 주세요.`를 표시한 뒤 기존 로그인 흐름에 연결한다. 원래 탭의 입력과 QR 이름은 유지한다. 비로그인 직접 다운로드에는 이 인증 만료 처리를 적용하지 않는다.

삭제되었거나 권한이 없는 QR의 다운로드는 `이 QR을 다운로드할 수 없어요. 내 QR 목록을 새로고침해 주세요.`를 표시하고 `목록 새로고침`으로 서버 목록을 다시 조회한다. 해당 경우 파일 재시도는 제공하지 않는다. 사용자가 브라우저의 파일 저장을 취소한 행동은 서비스 실패로 표시하지 않으며, 파일 준비 성공만으로 기기에 저장 완료됐다는 문구를 표시하지 않는다.

오류 안내는 보조 기술에 전달하고 입력 오류는 해당 필드와 연결한다. 재시도와 보기·가리기 버튼에는 키보드 포커스를 명확히 표시한다. 실패 시 입력값·비밀번호·연락처 내용·서버 내부 오류를 오류 문구나 로그에 덧붙이지 않는다.

### 보완 UI의 검사 기준

- 비밀번호 보기·가리기는 마우스와 키보드로 동작하며 입력·페이로드가 바뀌지 않는다. 공개 네트워크 전환과 유형 이동 후 다시 돌아오면 기존 값은 가려져 있다.
- 용량 초과와 생성 실패에서 이전 미리보기가 사라지고 다운로드·저장이 불가능하다. 수정 또는 허용된 재시도 후 정상 미리보기로 복구된다.
- 저장 실패에서 창·QR 이름·입력을 유지하며, 요청 중 중복 제출과 불명확한 응답 뒤의 중복 저장을 방지한다.
- 다운로드 실패에서 대상 QR과 형식을 유지하며 재시도가 가능하다. 비로그인 다운로드에는 인증·저장 요청이 없고, 계정 다운로드의 인증 만료와 삭제·접근 불가 응답은 각 복구 흐름으로 이동한다.
- 위 검사 항목은 해당 UI와 API를 구현한 단계에서 실제 동작으로 확인한다.

## 확인 기준

1. 다섯 유형 모두 유효한 입력으로 QR을 생성하고, QR을 다시 읽으면 의도한 페이로드와 일치한다.
2. 필수값 누락과 잘못된 주소·이메일에서는 QR 다운로드·저장이 불가능하고 수정 위치를 알 수 있다.
3. PNG와 SVG를 열어 같은 QR 내용, 흰 배경, 4모듈 여백을 확인할 수 있다.
4. 유형을 전환했다가 돌아오면 해당 유형의 입력값이 유지되고, 저장하지 않은 입력은 새로고침 후 남지 않는다.
5. 데스크톱에서 입력, 다운로드, 로그인, 내 QR 관리가 가능하다.
6. Wi-Fi와 연락처 QR은 대표적인 Android·iOS 카메라로 실제 스캔 동작을 확인한다. 기기별 앱 동작이 다르면 QR에 담긴 내용과 사용자 안내를 함께 점검한다.
7. Wi-Fi의 `\`, `;`, `,`, `"`, `:` 및 앞뒤 공백이 스캔 후에도 원래 SSID·비밀번호와 일치하고, 공개 네트워크 QR에는 비밀번호가 들어가지 않는다.
8. 연락처의 성·이름이 각각 올바른 `N` 구성 요소로 저장되고, 한쪽만 입력한 경우에도 연락처로 인식된다.
9. 로그인 화면과 로그인 실패 화면의 `비로그인으로 사용하기`가 기존 입력을 유지한다. 비로그인도 다섯 유형을 생성·미리보기하고 PNG·SVG를 다운로드할 수 있다. 계정 저장 요청은 발생하지 않는다. 새로고침 시 미저장 입력은 사라지며 이미 받은 파일은 계속 스캔할 수 있다. 명시적으로 계정에 저장한 항목만 다시 로그인했을 때 내 QR에 나타난다.
10. 저장한 QR의 PNG·SVG를 다시 읽으면 원래 페이로드와 일치하고, 다른 계정에서 해당 항목에 접근할 수 없다.
11. 삭제 확인 후 서버에서 항목을 재조회하거나 다시 다운로드할 수 없다. 이미 받은 고정형 QR 파일은 그대로 사용할 수 있다.

## 결정 근거

URL은 쿠폰, 행사 안내, 제품 정보, 설문 등 여러 활용 사례를 하나의 유형으로 처리한다. [Bitly의 2025년 마케터 조사](https://bitly.com/pages/ta/qr-code-survey)는 이런 링크 대상의 활용 사례를 보여주지만, 전체 사용자 수요의 순위로 해석하지 않는다. 연락처는 [vCard 3.0 형식](https://www.rfc-editor.org/info/rfc2426/)에 맞는 데이터 구조를 사용하고, 이메일은 [`mailto:` URI](https://www.rfc-editor.org/info/rfc6068/)로 표현한다.
