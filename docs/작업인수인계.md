# 다른 컴퓨터에서 이어 작업하기

기록일: 2026-10-10. 저장소: `https://github.com/Unknown02-coder/QR_generator`. 최신 작업 브랜치: **`codex/url-qr-core`**. `main` 병합과 운영 배포는 아직 진행하지 않았다.

## 시작 방법

Git과 Node.js를 설치한다. 최소 Node.js 버전은 루트 `package.json`의 `engines`를 따르며, GitHub Actions 및 새 폴더 복원 검사는 Node.js 24로 실행했다.

```sh
git clone --branch codex/url-qr-core https://github.com/Unknown02-coder/QR_generator.git
cd QR_generator
npm ci
npm run dev
```

저장소 루트에서 실행한다. `npm ci`가 루트 `package-lock.json`을 기준으로 프론트엔드 workspace 의존성을 설치한다. 현재 프론트엔드 확인에는 GitHub OAuth 비밀값이나 `.env` 파일이 필요하지 않다.

- `http://localhost:5173/`: 실제 비로그인 QR 생성·PNG/SVG 다운로드.
- `http://localhost:5173/publishing.html`: 예시 데이터로 계정 화면과 실패 상태를 확인하는 퍼블리싱 미리보기.

기존 checkout을 갱신할 때는 미커밋 작업을 먼저 확인한다. `git fetch origin`, `git switch codex/url-qr-core`, `git pull --ff-only origin codex/url-qr-core`, `npm ci` 순서로 진행한다. 로컬 브랜치가 없으면 `git switch --track origin/codex/url-qr-core`로 만든다. 충돌이나 작업 유실을 해결하기 위해 강제 초기화하지 않는다.

## 우선 읽을 자료

1. `AGENTS.md`: 작업 규칙, 기술 선택, 사용자 흐름과 보안 기준.
2. `docs/설계안.md`: 확정된 기능과 정확한 화면 문구.
3. `docs/API명세서.md`: 노션에서 옮긴 서버 API 계약. API 10개는 모두 실제 서버 구현 전이다.
4. `docs/구현현황.md`, `docs/퍼블리싱.md`: 검사 결과와 컴포넌트 연결 지점.
5. `docs/design/QR_생성_전체_화면시안_수정본.svg`: Figma에 가져올 전체 수정본. 총 27개 화면이다. 가입·로그인 5개는 같은 줄에 통합되어 있다.

온라인 Figma는 직접 편집하지 않는다. 저장소 SVG를 수정하고 사용자가 Figma에 붙여넣는다. `QR_GitHub_가입로그인_와이어프레임.svg`는 부분 확인용 사본이며 전체 화면 기준은 수정본 하나다.

## 구현 상태와 다음 작업

- 실제 동작: URL·Wi-Fi·연락처·텍스트·이메일 입력·검증·미리보기, 비로그인 PNG/SVG 다운로드, 비밀번호 보기·가리기와 오류·재시도. 미저장 입력은 탭 메모리에만 유지한다.
- 퍼블리싱 예시: 로그인·내 QR·저장·다운로드·QR 삭제와 오류·인증 만료 화면. 예시 계정 전환은 실제 로그인·DB 저장이 아니다.
- SVG에만 추가된 항목: 신규 사용자 자동 가입/기존 사용자 로그인 안내, GitHub 인증 진행, 팝업 차단, 인증 완료 후 입력 화면 복귀 안내. **이 시안은 아직 웹앱 미반영**이다.
- 서버: 아직 없다. 인증은 GitHub 통합 가입·로그인이며 별도 이메일·비밀번호 회원가입 API를 만들지 않는다. 첫 인증 때 내부 계정을 생성한다.

다음 작업은 추가 인증 시안을 프론트엔드에 반영하는 것이다. 이후 API 명세 P01의 Java 21/Spring Boot/Gradle 인증 서버, 세션·CSRF·PKCE·별도 인증 창의 입력 복귀를 연결한다. 다음으로 P02의 PostgreSQL/Flyway·암호화 QR 저장·소유권·목록·QR 삭제, P03의 저장 페이로드 파일 재생성을 구현한다. 실제 인증에는 별도로 등록한 GitHub OAuth 앱의 환경 설정이 필요하며 비밀값을 Git에 넣지 않는다.

## 검사와 복원 확인

```sh
npm test
npm run typecheck
npm run build
npx playwright install chromium
npm run test:browser
```

Linux에서 Playwright 시스템 라이브러리도 설치해야 하면 `npx playwright install --with-deps chromium`을 사용한다. Windows에 설치된 Edge를 쓸 때는 PowerShell에서 `$env:PLAYWRIGHT_CHANNEL = 'msedge'`를 지정한다. 검사는 프로젝트가 제공하는 스크립트와 CI 설정을 기준으로 실행한다.

`npm run build`는 `frontend/dist/index.html`과 `frontend/dist/publishing.html`을 생성한다. `npm run preview`로 확인한다. 빌드 대상 브라우저 검사 2개는 `docs/퍼블리싱.md`와 README의 방법을 따른다.

이전 전체 검사: 단위 52개, 개발 서버 브라우저 16개, 빌드 대상 브라우저 2개 통과. SVG 통합 커밋 `38a0182`의 GitHub Actions도 성공했다. 이동 준비 시 GitHub에서 이 브랜치를 새 폴더로 clone하고 `npm ci`를 다시 실행해 복원 가능 여부를 검사했다. 다른 실물 컴퓨터에서의 실행을 대신하는 검사는 아니다.

새 사본 복원 검사 결과: `npm ci` 종료 코드 0, 단위 검사 52개 통과·실패/건너뜀 0, 타입 검사를 포함한 `npm run build` 종료 코드 0. 실제 앱과 퍼블리싱 예시의 HTML 두 파일 생성도 확인했다. 제품 실행 코드에서 이 컴퓨터의 사용자 폴더나 Codex 런타임 절대 경로를 참조하지 않는다.

`node_modules`, `dist`, `.test-build`, `.cache`는 재생성 가능한 의존성·빌드·검사 산출물이다. Git에 포함하지 않으며 새 컴퓨터에서 다시 만든다. 개발 서버 프로세스와 브라우저 탭의 미저장 입력은 이동되지 않는다. 코드·lock 파일·테스트·작업 계획·설계·API 명세·SVG·CI는 저장소에 포함되어 있다.
