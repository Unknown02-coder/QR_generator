## 설계와 시안 비교

확정된 흐름(데스크톱, 비로그인 미리보기, GitHub 로그인 후 저장, 내 QR의 다운로드 형식 선택, QR 삭제 확인)에는 충돌이 없다.

시안에 없는 상태는 QR 용량 초과/생성 실패, 저장 실패, 다운로드 실패다. 설계에는 오류 안내가 필요하다고 되어 있지만 해당 화면과 정확한 문구가 SVG에 없다. UI 단계에서 사용자에게 문구/표시 위치를 확인해야 한다. 모듈은 오류 원인을 반환하며 누락된 화면을 임의로 확정하지 않는다.

와이파이 정상 화면에는 비밀번호 필드가 있지만 보기/가리기 버튼 또는 아이콘이 없다(해당 그룹은 rect/text 요소만 포함). 설계에는 키보드로 조작할 수 있는 보기/가리기 버튼이 필수다. 와이파이 UI를 구현하기 전에 이 차이를 반영할 위치를 확인해야 한다.

PDF는 계정/서버 저장을 제외하고 모바일을 포함하는 이전 기획이다. 사용자가 확정한 흐름 및 AGENTS.md가 지정한 설계안을 구현 기준으로 삼는다.

설계에 있는 세부 동작 중 정적 시안만으로 확인할 수 없는 것: 로그인 팝업의 입력 유지, 와이파이 비밀번호 보기/가리기와 공개 네트워크 전환 후 복원, 키보드/보조 기술 동작, CSRF/PKCE, 암호화 및 소유권 검사, 실제 QR 스캔. 정적 화면에 보인다고 구현된 기능으로 간주하지 않는다.

## 구현 순서

1. URL 검증 및 공통 QR 생성 모듈: 원문 보존, 검정/흰색 SVG, 4모듈 여백, 실제 디코딩 검사.
2. React/TypeScript/Vite 데스크톱 URL 입력·미리보기: CSS Modules/변수, 시안 정상/오류 문구, 유효하지 않은 입력에서 이전 QR 제거. 저장/로그인은 서버 연결 전까지 완료로 표시하지 않는다.
3. 와이파이·연락처·텍스트·이메일 페이로드와 폼: 유형별 오류, 메모리에서 입력 유지, 스캔 검증.
4. Java 21/Spring Boot/Gradle, PostgreSQL/Flyway, GitHub OAuth2 세션 인증 및 CSRF/PKCE. 암호화 저장, 사용자별 소유권 검증, 내 QR 목록.
5. 저장된 페이로드에서 PNG 1024×1024/SVG 재생성, 다운로드 형식 선택, QR 삭제 확인. 실제 로그인/계정 격리/저장/재다운로드/삭제와 Android·iOS 기기 검증.

## 현재 단계

첫 단계의 URL 검증 및 공통 QR 생성 모듈을 구현했다. 웹 화면과 백엔드는 미구현이다. 작업 브랜치는 `codex/url-qr-core`이며 원격 push/merge/배포는 하지 않았다.

| 기능 | 현재 구현 | 아직 남은 작업 |
| --- | --- | --- |
| 웹 주소 | 주소 검증, 원문 보존, QR 행렬/SVG 생성 | 입력 폼, 정상/오류 미리보기 UI |
| 와이파이·연락처·텍스트·이메일 | 공통 생성기만 재사용 가능 | 각 페이로드 변환기, 폼, 오류 화면 |
| GitHub 로그인·QR 저장 | 없음 | OAuth2, 세션, CSRF/PKCE, DB, 암호화, 소유권 |
| 내 QR·다운로드·QR 삭제 | 없음 | 목록, 형식 선택, 1024px PNG, 저장 페이로드 재생성, 삭제 확인 |
| 접근성·실제 기기 검증 | 없음 | 키보드/보조 기술, Android·iOS 카메라 |

- 설치 시 npm audit: 취약점 0. 이는 설치 시 레지스트리 감사 결과이며 보안 검토 전체를 대체하지 않는다.
- 실제 SVG를 이미지로 변환해 독립 jsQR 디코더로 일반/한글/쿼리/fragment/마크업 형태 URL의 원문 일치를 확인했다. 모든 픽셀의 불투명 검정/흰색과 사방 4모듈 여백을 검사했다.

- 테스트를 먼저 작성하고 미구현 모듈로 인한 실패를 확인했다. URL 구현 후 앞쪽 공백 입력의 오류 분류가 잘못된 1개 실패를 확인했고, 공백 검사 순서를 수정하여 23개 통과 후 생성기 검사를 추가했다.
- 별도 읽기 전용 코드 검토: Critical/Important 지적 없음. 깨진 UTF-16 문자열이 URL 검증을 통과하는 Minor 지적 1개를 재현했다. 상위/하위 단독 surrogate 테스트 2개 실패를 확인한 뒤 주소 오류로 차단했고, 정상 이모지 주소의 원문 보존/디코딩까지 추가해 최종 39개 모두 통과했다.
- 브라우저 화면, 로그인, 저장, 파일 다운로드, 삭제, 실제 카메라 스캔은 아직 검사하지 않았다. 런타임 라이브러리의 예기치 않은 내부 오류 분기는 강제로 주입하지 않았다.
