# 비로그인 QR 생성·다운로드 구현 계획

**목표:** 승인된 설계안·로컬 SVG에 따라 다섯 유형 입력, 미리보기, 비로그인 PNG/SVG 다운로드를 실제 웹앱으로 연결하고 API 명세 사본을 GitHub에 보관한다.

**기준:** `docs/설계안.md`, `docs/design/QR_생성_전체_화면시안_수정본.svg`, `AGENTS.md`.

**구조:** React/Vite + CSS Modules. `qr/payload.ts`에서 유형별 검증과 변환, 기존 `qr/generate.ts`에서 QR 생성, `qr/export.ts`에서 PNG/SVG 파일 준비, 화면은 탭 메모리로 입력을 유지한다. 백엔드는 이번 단계에서 구현하지 않는다.

**실행:** 사용자가 ‘ㄱㄱ’로 승인한 작업을 현재 브랜치에서 직접 이어서 진행한다. 로그인·계정 기능은 서버 미구현 상태를 표시하며 성공을 모사하지 않는다.

## 작업과 검사

- [x] API 문서: 노션 공통 규칙·10개 상세 명세를 `docs/API명세서.md`로 옮기고 README/AGENTS에서 연결한다.
- [x] 페이로드: URL·WIFI·CONTACT·TEXT·EMAIL의 discriminated input을 받아 `{ok,payload}` 또는 필드 오류를 반환하는 `buildPayload`를 작성한다. 먼저 실패 테스트를 실행하고 Wi-Fi 특수문자·16진수·공백, vCard CRLF/줄접기/주입 방지, mailto 인코딩, 비정상 Unicode를 검사한다.
- [x] 내보내기: 같은 유효 QR에서 SVG Blob과 1024px PNG Blob을 만든다. 정수 크기 모듈·흰 여백을 보장하며 실제 브라우저 파일을 독립 디코더로 확인한다.
- [x] 화면: React/Vite 진입점을 만들고 시안의 입력·미리보기·다운로드 창·로그인 안내를 연결한다. 입력 오류·용량 초과·생성·다운로드 실패에서 이전 QR 노출과 중복 다운로드를 막는다. 유형 전환·비밀번호 가림·재시도·키보드·포커스·새로고침을 검사한다.
- [x] 검증: 새 의존성 설치 후 단위 검사 52개·Edge 브라우저 검사 6개, 타입 검사·프로덕션 빌드 통과. 구현 현황과 실행법 갱신.

**전달 절차:** 검증한 커밋을 `codex/url-qr-core`에 푸시하고 원격 커밋과 로컬 커밋이 같은지 확인한다. main 병합과 운영 배포는 별도 작업이다.

## 주의할 입력과 실패

- Wi-Fi 공개 네트워크로 전환해도 비밀번호 메모리는 유지하되 QR에 넣지 않는다.
- 연락처 긴 한글·이모지 줄 접기는 UTF-8 문자 중간을 자르지 않는다.
- 이메일 제목·본문의 &, ?, #, 줄바꿈은 인코딩하고 헤더 필드에는 줄바꿈을 허용하지 않는다.
- invalid/용량 초과 입력 뒤에는 이전 미리보기나 다운로드 대상이 남지 않는다.
- 형식 선택 창을 열 때의 QR을 다운로드하며, 파일 생성 실패 후 선택 형식과 입력을 유지한다.
